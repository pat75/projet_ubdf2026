<?php

namespace App\Console\Commands;

use Illuminate\Console\Command;
use Illuminate\Support\Facades\File;
use Intervention\Image\ImageManager;

/**
 * Ramene a 2000 px de cote maximum les originaux des books qui depassent.
 *
 * Le legacy acceptait n'importe quelle taille : des illustrations de
 * 8268 x 8268 px (68 Mpx) depassent `images.pixels_max` et ne s'affichent
 * pas. Aucune declinaison ne depasse 2000 px, l'exces ne sert donc a rien.
 *
 * L'original est deplace dans storage/app/originaux/<meme chemin> avant
 * d'etre remplace : rien n'est perdu, le dossier se supprime a la main une
 * fois le resultat verifie. La nouvelle date du fichier perime seule les
 * declinaisons en cache (GenerateurImages compare les dates).
 *
 * Reprenable : un fichier deja reduit ne depasse plus, il est ignore.
 * Les GIF sont laisses tels quels (souvent animes).
 */
class ReduireImagesCommand extends Command
{
    protected $signature = 'ubdf:images:reduire
        {--max=2000 : Cote maximum en pixels}
        {--dry-run : Liste les images a reduire sans rien modifier}';

    protected $description = 'Reduit a --max px de cote les originaux des books trop grands (original sauvegarde)';

    public function handle(ImageManager $manager): int
    {
        $max = (int) $this->option('max');
        $essai = (bool) $this->option('dry-run');
        $racine = storage_path('app/public/books');
        $sauvegarde = storage_path('app/originaux');
        $vus = $reduits = $erreurs = 0;

        // books/<a>/<b>/<c>/<login>/<fichier> : les originaux seulement, pas
        // les sous-dossiers (img_cms, cms).
        foreach (glob($racine.'/*/*/*/*/*.{jpg,jpeg,JPG,JPEG,png,PNG,webp,WEBP}', GLOB_BRACE) as $fichier) {
            $vus++;
            $taille = @getimagesize($fichier);

            if ($taille === false || max($taille[0], $taille[1]) <= $max) {
                continue;
            }

            $relatif = substr($fichier, strlen($racine) + 1);
            $this->line("{$taille[0]}x{$taille[1]}  {$relatif}");

            if ($essai) {
                $reduits++;

                continue;
            }

            try {
                $temporaire = $fichier.'.reduction.'.pathinfo($fichier, PATHINFO_EXTENSION);
                $manager->decodePath($fichier)->scaleDown($max, $max)->save($temporaire, quality: 90);

                File::ensureDirectoryExists(dirname($sauvegarde.'/'.$relatif));
                File::move($fichier, $sauvegarde.'/'.$relatif);
                File::move($temporaire, $fichier);
                $reduits++;
            } catch (\Throwable $e) {
                @unlink($temporaire);
                $erreurs++;
                $this->components->error("{$relatif} : {$e->getMessage()}");
            }
        }

        $verbe = $essai ? 'a reduire' : 'reduites';
        $this->components->info("{$vus} images lues, {$reduits} {$verbe}, {$erreurs} erreurs.");

        return $erreurs ? self::FAILURE : self::SUCCESS;
    }
}

J'ai créé une commande artisan, ubdf:images:reduire, dans ReduireImagesCommand.php. Elle ramène à 2000 px de côté maximum tous les originaux des books qui dépassent. Le test passe ; en local, l'essai à blanc trouve 389 images à réduire sur 13 611. Rien n'est encore déployé ni lancé sur le serveur.

Comment elle fonctionne :

Elle parcourt storage/app/public/books/<a>/<b>/<c>/<login>/ (jpg, png, webp). Les sous-dossiers img_cms et cms ne sont pas touchés.
Elle lit seulement l'en-tête de chaque fichier pour connaître sa taille : le parcours est rapide.
Elle réduit l'image avec Imagick en gardant les proportions (une image de 8268 × 8268 devient 2000 × 2000), en qualité 90.
Avant de remplacer un fichier, elle range l'original dans storage/app/originaux/<même chemin>. Rien n'est perdu ; ce dossier se supprime à la main une fois le résultat vérifié.
Les déclinaisons déjà en cache se régénèrent seules, car le fichier réduit porte une date plus récente.
On peut l'interrompre et la relancer : une image déjà réduite ne dépasse plus, elle est ignorée.
Les GIF ne sont pas touchés, car ils sont souvent animés.
Après le déploiement, sur o2switch, en tâche de fond comme organiser :


ssh o2switch-ubpro
cd ultra-book.pro
php artisan ubdf:images:reduire --dry-run | tail -5    # combien d'images, sans rien modifier
screen -S reduire-images php artisan ubdf:images:reduire 2>&1 | tee storage/logs/reduire-images.log
# Ctrl-A puis D pour détacher ; screen -r reduire-images pour revenir
Une fois les images réduites, plus aucune ne dépasse la limite pixels_max. L'ajout de IMAGES_PIXELS_MAX dans .env.prod n'est donc plus nécessaire.

Pensez à vérifier l'espace disque avant : la copie des originaux occupe de la place jusqu'à ce que vous supprimiez storage/app/originaux.
